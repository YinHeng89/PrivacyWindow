- 审查方式：静态走查 + 全量编译验证（`./build.sh --keep-version` 通过，产物签名有效）

## 0. 设计纠偏（相对 v1）

v1 把颜色在 `BlurProcessor` 里**烤进**模糊图（精确模式），又在 `NSVisualEffectView` 上**另起一层** `tintLayer`（降级模式）—— 两套染色逻辑，被判定为「两套模式」。

v2 改为：**模糊逻辑完全不动**，颜色只作为「模糊之上的一层」来做，两种渲染后端共用同一个 `tintLayer` 机制。对齐原始需求「在之前模糊的基础上可以调颜色」。

---

## 1. 变更概述

在「外观 › 模糊半径」下方新增「模糊颜色」与「颜色强度」两项设置，给模糊背景叠加任意颜色。

- **模糊本身**：`BlurProcessor.blur()` 现在是一个**纯高斯模糊**，不再接触任何颜色（删除了 `BlurTint` 结构体与烤色逻辑）。
- **着色**：`BlurOverlay` 持有一个统一的 `tintLayer`，在两种后端里都创建：
  - 精确模式：作为 `hostLayer`（承载模糊图）的子层，**加在挖洞描边环之前**，故描边仍浮于颜色之上；
  - 降级模式：作为 `NSVisualEffectView.layer` 的子层。
  - 两者都**继承所在层的 even-odd 挖洞遮罩**，焦点窗口/光标盘/自身窗口/排除应用均保持清晰。
- **默认**：颜色 = 白色、强度 = 0 → 着色层透明，视觉与改动前完全一致（向后兼容）。

## 3. 正确性评估

### 3.1 着色机制（核心）
着色现在是「模糊内容之上的一层纯色 CALayer」，靠 `opacity`（= 强度）做 source-over 混合：`result = tint·α + blurred·(1−α)`。

- α = 0：层透明，保持原模糊（与旧行为一致）。✅
- α = 1：纯色填充。✅
- 颜色层叠在**已模糊**内容之上，符合「在模糊上叠一层纯色」的直觉；且不改写模糊像素，焦点窗口的清晰内容透过挖洞正常显示。✅
- 单一机制覆盖两种后端，不再有「精确烤色 / 降级叠层」的分叉，避免两条路径行为漂移。✅

### 3.2 挖洞清晰度
`tintLayer` 是 `hostLayer`（精确）或 `effect.layer`（降级）的子层，二者均被 `maskLayer`（even-odd 全屏减挖洞）遮罩。因此着色层**同样被挖洞**，焦点窗口/光标盘/自身窗口/排除应用穿过着色清晰可见。✅

### 3.3 值域夹紧
`amount` 在 `setBlurTintAmount` 与 `applyTint` 两处都被 `min(max(_, 0), 1)` 夹紧；滑块 step 0.05、范围 0…1。✅ 无越界。

### 3.4 持久化
十六进制字符串（RRGGBB）存 `UserDefaults`；`colorFromHex` 对长度/解析做了保护，异常回退白色。✅ 取色器为不透明色，`NSColor` 不带 alpha，符合设计。

### 3.5 设置绑定
`Color` ↔ `NSColor` 经 `Color(NSColor)` / `NSColor(Color)` 互转（macOS 11+），sRGB 往返稳定；强度文本取自 `wrappedValue` 避免对 `Binding` 直接运算的编译错误。✅

### 3.6 `clear()` 与 `commit()` 的着色自恢复
- `clear()`（空桌面、无焦点窗口）把 `tintLayer.opacity` 置 0，但**保留** `tintColor`/`tintAmount`。
- `commit()` 每次完成实质提交（reveal 变化或新图到达）时调用 `applyTint()`，把记忆中的色值重新推回层上。因此焦点窗口从「无」回到「有」时，着色自动恢复，不会卡在透明。✅
- 早退路径（`guard revealChanged || pendingPicture != nil`）不重断言，但因为无任何变化，着色状态本就正确，不影响。✅

### 3.7 编译
全量 Release 构建通过（增量重编 `PrivacyCore` 等目标），产物 `build/PrivacyWindow.app` 签名有效。✅

## 4. 风险与边界（相对 v1 已收敛）

- **R1（低风险→已实现）挖洞边缘明暗自适应**：`updateEdge` 依「洞周围模糊区亮度」选黑/白描边，原亮度取自 `surroundLuminance`（补色环平均色，不含叠加的着色）。强染色时背景实际色被染，描边对比度会略降。**已实现**：`setTint` 现在把 `tintColor` 的 Rec.709 亮度存入 `tintLuminance`，`edgeTone()` 改用「按 amount 混合 raw 背景与着色亮度」的有效亮度（`luminance*(1−α)+tintLuminance*α`）做判定，强染色下描边仍可读。
- **R2（中风险→已实现）降级模式 tintLayer 稳定性**：`NSVisualEffectView` 在系统更新或切换 `material` 时可能重建其 layer，导致挂上去的 `tintLayer` 子层丢失，着色短暂失效。**已实现**：新增 `reattachTintIfNeeded()`，在 `applyTint()`（每次 `commit`/`setTint` 都会走）与 `setBlurRadius()`（改 material 后立即）中检测 `tintLayer.superlayer == nil` 时重新挂回 `vibrancyView.layer`（精确模式则插到 edge 环之下，保证描边仍压在着色之上）。
- **R3（已消除）并发模型**：v1 在 `Task.detached` 中跨越边界传递含 `NSColor` 的 `BlurTint`，Swift 6 严格并发下会报警。v2 已彻底删除该结构，`captureOnce` 不再构造/传递任何着色数据——着色完全在 main 上经 `setTint` 处理。此项风险消除。✅
- **R4（信息）滑块拖动触发重新截图**：`setBlurTintColor/Amount` 仍会 `settledFrames = 0` 唤醒截图循环。v2 着色是实时层、无需重新截图，此唤醒属冗余（每步重渲同一张模糊图），开销可忽略。*可选优化*：若追求极致，可仅对半径/光标类改动重置 `settledFrames`，着色改动不必唤醒截图。

## 6. 结论

v2 回归需求本质：模糊保持不变，颜色作为模糊之上的一层统一着色机制，两种渲染后端共用同一份代码，消除了 v1 的「两套模式」分叉。核心混合数学正确、挖洞清晰度经遮罩继承得到保证、`clear`→`commit` 自恢复闭环、`NSColor` 跨并发边界的问题随 `BlurTint` 删除一并消除。两项可选增强（R1 着色亮度参与边缘判定、R2 降级模式 `tintLayer` layer 重建自愈）现已落地，全量编译通过（签名有效，v0.1.22）。**建议合并。**
