# 代码审查记录（2026-09-18）

三位方向不同的评审（AppKit/并发、图形渲染、安全隐私+测试）对整个仓库做了一次**只读**审查，没有改动任何代码。下面按严重程度汇总，**每条的行号我都抽查过是真存在的**（抽查了 `PrivacyController` 1099/947/693、`BlurProcessor` 116、`BlurOverlay` 133），但结论本身尚未逐个复现，动手前请自己再看一眼上下文。

审查基准：本次审查时的 HEAD，仓库约 5800 行 Swift，68 个单元测试。

## 值得先修的（P0 / P1）

### 1. 每帧两次 GPU→CPU 回读，5K/双屏下会明显滞后
`BlurProcessor.swift:117`、`BlurProcessor.swift:215`、`BlurOverlay.swift:276`

`context.createCGImage(...)` 每帧把模糊结果从 GPU 拉回 CPU 堆，再交给 `CAShapeLayer.contents` 让 Core Animation 重新上传。**5K 或外接多屏时这趟来回是几十毫秒级**，表现为「拖动窗口时后面的模糊跟不上」。

同步读两个抗辩点：
- 全屏 RGBA8 约 6MB/帧，普通堆对象在内存压力下会被换出到 swap —— 这跟「画面只在本机内存中处理」的说法有落差。真要较真，输出应该走 IOSurface 或对缓冲区 `mlock`。
- 优化方向：全程 IOSurface/Metal，别回读。

### 2. 每次洞变化都重建全屏路径并重栅格化
`BlurOverlay.swift:296`、`BlurOverlay.swift:688`

reveal 一变就重建整屏 even-odd 路径并做 `CGPath` union，shape layer 以 2x 重新栅格化整屏。开鼠标圆盘或拖窗时会掉帧、风扇响。建议静态蒙版固定为一层，鼠标圆盘单独一层交给 GPU 合成。

### 3. 采集流每帧现建现拆
`ScreenCapturer.swift:166`、`PrivacyController.swift:436`

现在是每帧创建/销毁 SCK stream，8ms 间隔无背压连拍。改成常驻 `SCStream` 帧回调并对齐 display link 丢帧，固有延迟和功耗都会降一个量级。

### 4. 运行中途授予权限 → 可能整屏不再模糊
`PrivacyController.swift:891`

检测到权限就把 vibrancy 切成截图后端，**新覆盖层要等首帧才有内容**；而 TCC 权限通常是「每进程读一次」，grant 后可能一直拿不到画面。更糟的是无焦点窗口时 `captureOnce` 会提前 return（`PrivacyController.swift:1227`），重试计数不递增，重启提示（`:933`）也永远不触发 —— 变成静默失效。

建议：旧覆盖层保留到新后端交付首帧，watchdog 加超时兜底。

### 5. 权限提示可能点不动
`PrivacyController.swift:702`、`:947`；相关：`BlurOverlay.swift:133`

sheet 挂在 `OverlayWindow` 上，而那个窗口 `ignoresMouseEvents = true`、无标题栏（`canBecomeKey` 默认 false），app 又是 `.accessory`，`NSApp.activate`（`:690`）对它无效 —— **按钮有可能根本点不了，权限就成了死局**。这条我判断为高优先级但**未实测**，值得专门验一次。

### 6. 「建议重启」提示用了模态 runModal
`PrivacyController.swift:950`

`showRestartHint()` 在没有宿主窗口时退回 `alert.runModal()`，跟 `:697` 注释里自己写的「阻塞主线程正是要避免的那个失败」直接冲突。嵌套 run loop 会卡住 display link 与捕获循环。改无模态提示。

### 7. 关窗 250ms 内重开 → Dock 图标永久残留
`SettingsWindow.swift:509`、`:592`

关窗时置 `raisedActivationPolicy = false` 并延迟 250ms 恢复 `.accessory`；这 250ms 内再开设置时 `open()` 因为 policy 仍是 `.regular` 就不再置位，只取消了恢复定时器 —— 再关一次，Dock 图标和 ⌘Tab 项就再也退不掉。取消恢复时要同步把标志位恢复。

### 8. 锁屏/屏保期间仍在读窗口元数据
`PrivacyController.swift:978`、`:659`、`:634-656`

`suspendForPower()` 只停了抓帧，display link 仍以 60Hz 跑主线程，并且每 3–6 帧全量 `CGWindowListCopyWindowInfo` 一次。这意味着**屏保/锁屏期间仍在读窗口服务器的窗口标题与几何**，跟「权限最小化」的承诺不符合。暂停信号也缺 `sessionDidResignActive`、`sessionDidLogout`、`willPowerOff` 三个场景。

另外锁屏后要 15 帧（`:174` `focusLossGraceFrames`）才 `clear()`，最后一帧真实画面会在 layer contents 上多留一会儿。

### 9. 每帧一次布尔起作用的写法有 Bug
`PrivacyController.swift:1099`

```swift
if candidate != nil, powerPaused,
   !Self.isScreenLocked() || Date.timeIntervalSinceReferenceDate - powerPausedAt > Self.maxPowerPause {
```

`&&` 优先于 `||`，所以「10 秒兜底」那半句脱离了 `powerPaused` 前置条件恒为真（`powerPausedAt` 初值是 0），**每个帧都会调 `resumeFromPower()`**。加括号就行。

### 10. 排除应用的 app 没在跑时，每帧全量枚举
`PrivacyController.swift:363`

`|| excludedWindows.isEmpty` 让空结果也失去缓存效果，每帧都全量枚举窗口并对每个 PID 查一次 `NSRunningApplication`。空结果也应该按帧间隔缓存。

## 次要问题（P2）

- **屏幕签名只含 frame**：`PrivacyController.swift:737`、`BlurOverlay.swift:158/170`。改分辨率或缩放不触发重建，`contentsScale` 过时、蒙版边缘会发虚错位。签名应加入 `backingScaleFactor`。
- **降级路径边缘阴影不画**：`BlurOverlay.swift:350`。vibrancy 模式下 `hasPicture` 永为 false，视觉上跟有权限时不一致。用固定色或材质色调替代亮度采样。
- **vibrancy 分支没挂 `hostLayer`**：`BlurOverlay.swift:172`。降级模式永远画不出挖洞描边。
- **屏幕签名漏了就 smear**：`ScreenCapturer.swift:177/191`。已判定 SCK 拒绝降采样却仍把该帧放大裁切图返回 —— 偶发一帧整屏错位。该帧应直接丢弃返回 nil。
- **capturer 状态不清账**：`ScreenCapturer.swift:42/60/75`。`filters` / `failures` / `downscaleDisabledUntil` 按 displayID 累积，拔屏后不清；也没有 `deinit`，反复开关会一直跑剩余的 `SCShareableContent` 枚举任务。
- **排除应用列表明文存 UserDefaults**：`PrivacyController.swift:342/291` → `~/Library/Preferences/com.privacywindow.PrivacyWindow.plist`。未启用 App Sandbox，**同机任意用户级进程可 `defaults read` 读到「你信任哪些 App」**，还会随 Time Machine 备份带走。自用可接受，但这是「隐私工具」的自相矛盾处。

## 测试：薄弱点在哪

68 个用例里约 40 个集中在纯几何（`maskPath` / `cornerRadii` / `isBar` / `divisor`），**状态机几乎零覆盖**：启停、后端切换、电源暂停、`captureOnce` 的 generation/stall 退避、多屏并集、权限切换、display change 重建，全都没测。纯函数抽离做得不错，可测性底子好，缺的是把状态机也抽成无副作用的形式。

另外两处质量问题：
- `ExcludedAppsTests:758` 直接读写 `UserDefaults.standard` 再 defer 还原 —— 会污染开发机的真实偏好，应该用注入的存储。
- `VibrancyMaterialTests:600` 只断言 4 个值互不相同，属于「测了个寂寞」。

**最值得补的 5 个用例**
1. 权限中途授予 → 从 vibrancy 切到 captured、overlay 全重建、`runsOnVibrancyFallback == false`、捕获循环重启。
2. 权限中途撤销 → 切回 vibrancy、`captureTask == nil`、待首帧标志清空（不误弹重启提示）。
3. 锁屏 → `captureTask == nil` 且所有 overlay contents 为 nil；解锁且 focus 非空后恢复。
4. 跨屏 inpaintingHole：窗口横跨两屏，断言并集覆盖新旧位置、不越各屏边界、坐标系翻转正确。
5. 失败退避：连续失败后重试间隔按 0.25→2s 增长，且 `downscaleDisabledUntil` 只影响该 display。

## 如果只修三件事

1. **第 9 条**（运算符优先级）—— 一行的事，但它在每帧都做无用功。
2. **第 8 条**（锁屏仍在读窗口元数据）—— 这是隐私工具的核心承诺被打折。
3. **第 1/2/3 条**（渲染管线）—— 决定它在你的 5K 屏上是「跟得上」还是「拖影」，体验差距最大。

第 5 条（权限提示点不动）建议先手动验一次：删掉权限，重启效果触发提示，看按钮能不能点。
