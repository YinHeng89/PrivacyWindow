# 隐私窗口 (PrivacyWindow)

一个常驻菜单栏的 macOS 小工具：**只让当前焦点窗口保持清晰，其余所有背景全部高斯模糊**。

效果类似 HazeOver，但用「模糊」而不是「变暗」——打开后，屏幕上除你正在用的那个窗口之外的一切（其他窗口、菜单栏、桌面）都会被实时模糊盖住，只有焦点窗口透过透明挖洞露出来，并且仍然可点击、可交互。

## 原理

- 用 **ScreenCaptureKit** 持续对每张屏幕截图（拖动时全速，桌面静止后降到 ~30fps），并排除本 app 自身的窗口，避免覆盖层自己被拍进去。
- 糊之前先把焦点窗口所在的矩形「补色」成周围一圈的平均色，再用 `CIGaussianBlur` 模糊。这一步是消除窗口周围白光晕的关键：模糊只会在相邻像素间扩散，洞里已经没有亮像素可以往外晕了。
- 用一个置顶、透明、不接收鼠标事件的 `NSWindow` 覆盖整屏显示模糊图。
- 用 `CGWindowListCopyWindowInfo` 找到当前最前应用的最上层窗口，在覆盖层上以 **even-odd 路径挖一个透明矩形洞**，让真实的焦点窗口透出来。
- 挑窗口时会跳过「全宽、极扁、且贴着屏幕上/下边缘」的条状窗口：Chrome 全屏时会把下滑工具栏放在一个独立窗口里，而它排在浏览器窗口之前；把它当成焦点，挖出来的洞就是屏幕顶部的一条横杠。**必须同时贴边**：只看比例的话，2560×1440 以上（尤其超宽屏）的屏上，一个被拖成「80% 宽 × 30% 高」的普通浏览器窗口和 Chrome 工具栏在比例上完全一样，会被误杀掉。
- 挑窗口不是简单地「取最上面那个」，而是**先候选、再分层**（顺序错了就是这类 bug 的全部来源）：
  1. **layer 8–18 的对话框，不论属于谁**。它们在最前面是因为有人特意把它们摆在最前面，而「被问的那个 app」往往并不是当前最前的 app —— 后台 agent 弹面板时可以完全不激活自己，于是它的模态面板盖在所有东西之上，而系统仍认为另一个 app 在最前。把「最前 app 自己的窗口」排在第一，拿到的就是对话框**背后**那个窗口，洞会留在背景上。（这正是上次「连接服务器」那个 bug 的另一半。）
  2. **当前最前 app 自己的窗口**。这条防线用来挡住别家 app 的置顶装饰物（桌面宠物、歌词 HUD、悬浮球）—— 它「看得见」不等于「正在被用」。因此别家 app 的 **utility 层（19）**面板会落到下一层，而不是压过当前 app。
  3. **其他任何可用窗口**：空桌面、菜单栏 app、由不激活自己的 agent 弹出的面板，都靠这一层才有洞。都没有就不给焦点、全屏清晰 —— 对这个 app 来说，「丢掉整个模糊」是最不该发生的失败方向。
- 窗口层级按用途分三档：
  - **layer 0**：普通窗口，任何 app 都算。
  - **layer 8 及以上**：系统对话框带 —— 模态面板、认证弹窗、宗卷选择框。它们在最前面是因为有人特意把它们摆在最前面，所以不论属于谁都能当焦点。（「连接服务器」那次的坑：小的「正在连接 smb://…」浮条能当焦点，它弹出的宗卷选择框是模态面板却被层级上限挡掉；随后发现的一半则是：即使层级对，它属于不激活自己的后台进程时，也会被「最前 app 优先」那一步挤掉。）
  - **layer 1–7**：置顶装饰带 —— 浮动 HUD、桌面宠物、歌词条、贴边浮层。只认最前 app 自己的窗口（Quick Look 预览、浮动面板正落在这里），免得别家 app 的宠物抢走焦点。
  - 上限是 Dock（20）：Dock、菜单栏（24）、弹出菜单（101）等永远不能成为焦点。实测确认过这条上限不能放松：Dock 的窗口矩形是**整块屏幕**（layer 20），一旦放行，整屏都会被当成「焦点窗口」。
- 小窗口（小于 120×80）不会被直接否掉，只是**优先级靠后**：一个已经被拖小的合法窗口（迷你播放器、窄工具面板）如果因为尺寸被彻底排除，桌面就会「没有任何可聚焦窗口」，结果是所有覆盖层清空、整屏变清晰。真到只剩这些细碎窗口时，它们仍然能拿到焦点。
- 焦点窗口（连同它的投影）不参与截图，所以它在模糊背景上没有任何边界。因此在洞外画了一圈很淡的**窗沿阴影**（6 层递减描边，共 12pt），并按洞周围背景的明暗自动选黑或白 —— 纯白窗口压在白色背景上也能看清轮廓。阴影画在遮罩层内部，会被挖洞路径裁掉，绝不会盖到窗口上。
- 洞的位置由 **`CVDisplayLink`（与屏幕刷新同步）** 每帧读取，并和模糊图在同一个 `CATransaction` 里提交 —— 两者永远属于同一帧，不会错位。
- 焦点切到别的屏时，洞跟着切到对应屏幕。

## 构建与运行

需要 macOS 14+ 与 Xcode 命令行工具（`Package.swift` 是 swift-tools-version 6.0，所以需要 Swift 6 工具链 / Xcode 16+）。

```bash
./build.sh --run      # 编译、签名并启动
```

### 版本号

每次构建前 `build.sh` 会先把当前版本摆出来，等你确认：

```
PrivacyWindow — 构建前确认版本号

  当前版本  0.1.0 (build 1)
  自增版本  0.1.1 (build 2)

  回车        自增到 0.1.1
  版本号      手动指定，如 1.2.0
  patch/minor/major   指定自增哪一段
  k           保持 0.1.0 不变
  q           不构建，退出

  请选择 >
```

版本号写在 `Resources/Info.plist`：`CFBundleShortVersionString` 是「关于」页显示的版本，`CFBundleVersion` 是构建号、只增不减。默认自增 patch 段并让构建号 +1，所以每次装进 `/Applications` 的 `.app` 都能对上一次构建。

非交互环境（CI、被脚本调用）无法提问，默认取自增。不想每次被问，可以直接给参数：

```bash
./build.sh --version 1.2.0       # 直接指定版本号
./build.sh --bump minor          # 自增 minor 段（默认 patch）
./build.sh --keep-version        # 保持现有版本不动
```

写 plist 用的是行级替换而不是 `PlistBuddy` —— 后者会把整个文件重写一遍，**丢掉里面所有 XML 注释**。发布流水线（`Scripts/stamp-version.sh`）仍然以 git tag 为唯一来源覆盖这个值，tag 才是对外的真相。

单元测试覆盖纯几何与策略逻辑（降采样除数与请求比例、跨屏挖洞圆角、窗口过滤规则、**窗口挑选的分层顺序**、小窗口兜底、覆盖判定、**多露出形状的掩膜并集**——包括防 even-odd 抵消的回归用例、圆盘贴边不变形、光标跨屏归属），不需要屏幕录制权限，也不需要显示器：

```bash
swift test            # 需要完整 Xcode —— 命令行工具里没有 XCTest
```

代码分为两个 target：`PrivacyCore`（应用逻辑，可被测试导入）与 `PrivacyWindow`（仅入口）。可执行 target 无法被测试模块导入，这是拆开的唯一原因。

首次点击菜单栏「启用隐私模糊」时，macOS 会弹出 **屏幕录制** 权限请求，允许后才会生效。

若没授权，效果会「看起来开着其实不工作」，所以会在 1.5s 后弹一个说明。它是**挂在自己覆盖层上的 sheet**（不是 `runModal()`）：模态循环会独占主线程，期间的显示链路每帧 tick、截图、乃至菜单栏里的「停用」都排在它后面 —— 而弹窗文字本身让用户在之后去点那个菜单项。没有覆盖层可挂载时就不弹。

另一处弹窗是「授权已生效但本进程读不到，需要重启」的提示（触发条件是有过真实抓取尝试、但 6 秒内一帧都没送达，这是陈旧 TCC 授权的特征）。它也优先挂 sheet，但**没有宿主窗口时会退化成 `runModal()`** —— 此时效果基本等于没启用、覆盖层也不在屏上，阻塞主线程的代价很小。这一处跟上面的原则其实是冲突的，见 `docs/代码审查-2026-09-18.md` 第 6 条。

签名身份用 `SIGN_IDENTITY` 指定；也可以把它写进仓库根目录的 `.sign-identity`（已加入 `.gitignore`），`build.sh` 会自动读取：

```bash
echo 'Developer ID Application: Your Name (TEAMID)' > .sign-identity
./build.sh --run
```

不指定时退回 ad-hoc 签名（`-`），此时每次重新编译都会换一套签名，而 macOS 是按签名记 **屏幕录制** 权限的 —— 所以权限会被反复重新索要，旧的授权还得手动删掉。换成 Developer ID 后 Team ID 固定，授权就能一直生效。

## 使用

菜单栏图标（自定义的「眼睛带斜杠」模板图标；app 图标则是另一幅「窗口浮在模糊桌面上」的图稿）：

- **左键**：默认弹出菜单；可在设置里改成「开关模糊」或「打开设置」。右键任何时候都弹菜单。
- **设置…**（⌘,）：打开设置窗口，所有选项都在里面。

设置窗口是侧边栏分页（通用 / 外观 / 行为 / 关于）+ 底部搜索，⌘1–⌘4 切页、⌘K 跳到搜索框、⎋ 清除。搜索会跨全部分页匹配，命中的小节逐个出现，没命中的页面不占地方。

它**没有放到覆盖层之上**：高窗口层级会让 macOS 自己的截图工具也截不到那个窗口，而且在 Mission Control 里行为怪异。取而代之的是，`Reveal` 的第三个成员把本 app 自己的窗口也挖出去 —— 设置窗口所在的那块区域不会被模糊，效果一样，但系统 z 序没被动过。

四类露出形状（焦点窗口、鼠标圆盘、本 app 自己的窗口、排除应用的窗口）**共用同一个圆角值** `BlurOverlay.cornerRadius`（当前 20）。自己的窗口和排除应用的窗口曾经另用一个写死的 12，于是调 `cornerRadius` 时它们不跟着变，四角会各留一小块模糊的尖角 —— 现在统一了。

自己的窗口**拿着键盘时，焦点窗口的洞会让位**：焦点挑选故意不认本 app 的窗口（否则挖的就是「自己的模糊」），所以打开设置时扫描会落到别家 app 最上面那个窗口上，于是「设置窗口 + 上一个窗口」两个都清晰。拿着键盘的窗口才是正在用的窗口，所以此时丢掉焦点洞，只留自己的窗口（以及排除列表里那些应用的窗口）；焦点窗口本身照旧被排除出截图并补色，因此它是被真正糊上的，而不是「没挖洞而已」。

页面右侧的滚动条被去掉了 —— 浅色窗口上那条 AppKit 滚动条读起来像渲染故障；滚轮、键盘与滚动手势照常工作。做法是在 SwiftUI `ScrollView` 的内容里挂一个 `ScrollerRemover`（`NSViewRepresentable`）拿到外层 `NSScrollView` 后把 `hasVerticalScroller` 关掉：光靠 `.scrollIndicators(.hidden)` 不行，那个 scroll view 是 SwiftUI 的对象，它后续自己的一次更新会把滚动条装回去（实测窗口起来两秒后 `hasVerticalScroller=true`、`scrollerStyle=legacy`，就是那条宽灰条）。所以每次 SwiftUI 更新本视图都再摘一次，并在窗口打开的头两秒内重试几轮。

焦点方面有一个 `LSUIElement` 应用的固有限制要绕：accessory 应用**无权拥有键盘**，窗口弹出来标题栏是灰的、输入框打不了字。因此设置窗口打开期间 app 会临时切回 `.regular`（Dock 里短暂出现一个图标、菜单栏短暂显示本 app 的菜单），关窗后 0.25 秒恢复 accessory。激活本身也踩过两个坑：菜单栏菜单关闭的瞬间系统会把焦点还给上一个 app，因此激活被推迟到下一个 run loop 回合并以 `isKeyWindow` 为准**重试最多六次**；`makeKeyAndOrderFront` 之后的 `orderFrontRegardless` 会把 key 状态冲掉，已删除。

菜单栏菜单点开后：

- **启用 / 停用隐私模糊**：开关效果。
- **模糊强度**：七档，20%–80%，对应模糊半径 10 / 15 / 20 / 25 / 30 / 35 / 40 pt。原来的轻度 / 中度 / 强度正好落在 20% / 40% / 80%。
- **菜单栏与 Dock 保持清晰**：默认开启。开启时覆盖层降到系统 UI 之下，菜单栏和 Dock 不被模糊、始终可用；关闭后它们会和其余背景一起被模糊。
- **全屏时停止模糊**：默认开启。焦点窗口铺满整块屏幕时（全屏 App），屏幕上已经没有需要隐藏的东西，于是停止模糊也不再截图。
- **鼠标周围保持清晰**：默认关闭。在模糊背景上以光标为圆心保持一个清晰的圆盘，方便看清指针附近的真实内容；「光标清晰范围」可选 60 / 120 / 200 pt，选档时自动开启。它只是掩膜上的又一个露出形状：圆盘下就是真实画面，不参与截图排除、不需要补色，也不用给它画窗沿阴影。
- **退出**。

设置窗口「行为」页还有**排除应用**：加入排除列表的应用，它的窗口**始终保持清晰**，与焦点在哪无关。所以从微信切到别的窗口时，微信的窗口清晰，切换过去的焦点窗口也清晰，只有其余区域保持模糊。它不是「位于前台时整个效果待机」——那会把整块桌面都还原。列表按 bundleID 持久化，添加时从正在运行的应用中选；窗口矩形每 6 帧从窗口服务器重读一次（约每秒十次），拖动时跟随足够及时。唯一例外是本 app 的设置窗口在最前时：那时焦点窗口的洞让位，但排除列表里的窗口照旧清晰。

所有选项（开关状态、模糊强度、菜单栏与 Dock、全屏时停止模糊、鼠标周围保持清晰）都会记在 `UserDefaults` 里，退出后下次启动自动恢复；上次退出时效果是开的，这次启动就直接是开的。设置窗口自身的两个偏好（左键动作、窗口配色）也一起持久化。

设置窗口直接绑定 `PrivacyController`（它是 `ObservableObject`），不存在第二份设置状态 —— 这也是菜单里改、窗口里看不会有分歧的原因。开/关状态另有**单一出口**（`onEnabledChanged`）：无论从菜单、设置窗口还是退出流程触发，菜单栏图标（停用时变暗 45%）和已打开菜单里的开关标题都从同一处刷新，不存在各界面各改各的。

## 两种模糊后端

效果有两种后端，会话启动时按权限自动选择，运行中授权状态变化时**1 秒内自动切换**：

- **截图后端**（默认）：`ScreenCaptureKit` 截屏 + `CIGaussianBlur`，半径 5–60 pt 精确可调，窗沿阴影按背景明暗自动选色。需要「屏幕录制」权限。
- **系统模糊后端（降级）**：未授权时自动启用。覆盖层里放的是 `NSVisualEffectView(.behindWindow)`，由系统合成器直接模糊下层内容，**不需要任何权限** —— 所以未授权时效果照常可用，而不是一片死寂。代价是强度只能按系统材质分四档近似（`hudWindow` / `underWindowBackground` / `fullScreenUI` / `menu`），滑块变成粗调；也没有窗沿阴影（拿不到像素就没法采样背景明暗）。

两者共用洞以下的全部逻辑：`Reveal` 的三个露出形状、even-odd 掩膜、并集防抵消、窗口层级、焦点挑选 —— 只有背景图不一样。设置窗口会如实标注当前处于哪种模式。

## 说明 / 已知取舍

- 开启「菜单栏与 Dock 保持清晰」（默认）时，覆盖层会降到系统 UI 之下，因此**层级高于菜单栏的界面不会被模糊**：状态栏下拉菜单、弹出菜单、输入法候选栏、通知横幅、Spotlight、Dock 上的拖拽影像等。这是「保证系统 UI 可用」的必然代价；关掉该选项可让覆盖层回到最高层，把它们一并糊上。
- 模糊是**视觉层面**的：覆盖层不拦截鼠标，因此模糊区域背后的窗口其实仍可点击（和 HazeOver 一致）。如果你需要「背景完全不可交互」，需要让覆盖层接收事件，但这会同时挡住焦点窗口的点击——本版本选择保持焦点窗口可交互。
- 多显示器：每张屏幕各有一层覆盖；焦点窗口在哪张屏，洞就挖在哪张屏，其余屏整体模糊。鼠标圆盘只画在光标所在的那张屏上，跨屏时圆盘整体跳到另一张屏的覆盖层、由各自的边界裁剪，不会出现半个圆。
- 有两个露出形状（焦点窗口 + 鼠标圆盘）时，掩膜会先对它们**求并集再挖洞**：even-odd 是异或，直接加两条子路径会让重叠区穿越次数变成奇数、被重新糊上——鼠标拖过窗口边缘时就是一块透镜形的糊斑。
- 截图会降采样到约 1600px 宽再放大显示：按屏幕宽度缩放，5K/6K 屏最多降到原像素的 1/4，1080p 屏则保持原样；Retina 屏按 `pointPixelScale / divisor` 请求（例如 2560px 宽、2x 的屏，divisor 1.6 → 请求 1.25 px/pt，正好落到 1600px），不会被「最多 1.0」的钳制截掉。模糊本来就会抹掉高频细节，肉眼看不出差别，但像素量（以及模糊开销、GPU→CPU 回读）显著下降，省下的延迟都用在了「跟手」上。
- 桌面静止约 0.75s 后，截图与窗口查询都会自动降频以省电；一旦焦点或窗口位置有变化立刻恢复全速。具体档位在设置窗口「行为」页里列了出来。

## 省电

这是一个常驻菜单栏的工具，所以「没事干的时候别干活」和效果本身一样重要。当前会在这些情况下停止或降低工作：

| 情况 | 行为 |
|---|---|
| 焦点窗口**全屏**（铺满整块屏） | 该屏停止模糊，并**停止截图** |
| 没有可聚焦的窗口（空桌面、锁屏、屏保） | 覆盖层清空 + 截图循环**完全停止** |
| 系统休眠 / 锁屏 / 屏保（通知） | 截图循环停止，唤醒或解锁后恢复 |
| 仅显示器睡眠后唤醒（`screensDidWake`） | 重建显示链路并重新截图 —— 系统休眠才会发 `didWake`，只睡显示器时不会 |
| 时钟自己停了（醒了没通知、未知原因） | 每秒查一次心跳，静默超过 1s 就换一条新的 `CVDisplayLink` |
| 桌面静止（约 0.75s 无变化） | 截图降到 ~30fps，窗口查询降到 1/2 |
| 没有洞的副屏 | 独立降到 ~15fps（整屏模糊，看不出差别） |
| 桌面长时间完全静止（约 15s 无变化） | 截图降到 ~4fps |
| 鼠标静止（鼠标洞开着时） | 洞集合不变就不重建掩膜，每帧只剩一次光标位置读取 |
| 截图失败（如未授权屏幕录制） | 指数退避 0.25s → 2s，不做无谓重试 |
| 关闭「隐私模糊」 | 所有定时器、任务、窗口全部释放 |

截图还会按屏幕宽度降采样（目标约 1600px 宽、最大 1/4）：屏越大降得越多，模糊本来就会抹掉高频细节，肉眼看不出差别，但像素量和 GPU→CPU 回读随之下降。

> 取舍：全屏时停用模糊，意味着那块屏幕上的一切都是清晰的。判定用的是「窗口是否**铺满整块屏**」而不是「覆盖了多少比例」——覆盖 90% 的窗口仍会留下一条真实的桌面，而那正是这个工具要遮住的东西。

## 技术方案选型

我们走的是 **ScreenCaptureKit 截屏 + `CIGaussianBlur` 自己算模糊**。另一条常见路线是 `NSVisualEffectView(.behindWindow)` 让系统合成器给模糊（QuietLens 就是这么做的）——它便宜、实时、不要屏幕录制权限，但模糊强度被系统预设的几档材质封死，改不动。

完整的逐项对比、可行性判定，以及「为什么建议补一条 Vibrancy 降级路线」见 **[docs/QuietLens-方案评估.md](docs/QuietLens-方案评估.md)**。
