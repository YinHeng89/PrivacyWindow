# 隐私窗口 (PrivacyWindow)

一个常驻菜单栏的 macOS 小工具：**只让当前焦点窗口保持清晰，其余所有背景全部高斯模糊**。

效果类似 HazeOver，但用「模糊」而不是「变暗」——打开后，屏幕上除你正在用的那个窗口之外的一切（其他窗口、菜单栏、桌面）都会被实时模糊盖住，只有焦点窗口透过透明挖洞露出来，并且仍然可点击、可交互。

## 原理

- 用 **ScreenCaptureKit** 持续对每张屏幕截图（拖动时全速，桌面静止后降到 ~30fps），并排除本 app 自身的窗口，避免覆盖层自己被拍进去。
- 糊之前先把焦点窗口所在的矩形「补色」成周围一圈的平均色，再用 `CIGaussianBlur` 模糊。这一步是消除窗口周围白光晕的关键：模糊只会在相邻像素间扩散，洞里已经没有亮像素可以往外晕了。
- 用一个置顶、透明、不接收鼠标事件的 `NSWindow` 覆盖整屏显示模糊图。
- 用 `CGWindowListCopyWindowInfo` 找到当前最前应用的最上层窗口，在覆盖层上以 **even-odd 路径挖一个透明矩形洞**，让真实的焦点窗口透出来。
- 挑窗口时会跳过「全宽、极扁、且贴着屏幕上/下边缘」的条状窗口：Chrome 全屏时会把下滑工具栏放在一个独立窗口里，而它排在浏览器窗口之前；把它当成焦点，挖出来的洞就是屏幕顶部的一条横杠。**必须同时贴边**：只看比例的话，2560×1440 以上（尤其超宽屏）的屏上，一个被拖成「80% 宽 × 30% 高」的普通浏览器窗口和 Chrome 工具栏在比例上完全一样，会被误杀掉。
- 挑窗口不是简单地「取最上面那个」，而是**先候选、再分层**（顺序错了就是这类 bug 的全部来源）：
  1. **layer 8–18 的对话框，不论属于谁**。它们在最前面是因为有人特意把它们摆在最前面，而「被问的那个 app」往往并不是当前最前的 app —— 后台 agent 弹面板时可以完全不激活自己，于是它的模态面板盖在所有东西之上，而系统仍认为另一个 app 在最前。把「最前 app 自己的窗口」排在第一，拿到的就是对话框**背后**那个窗口，洞会留在背景上。（这正是上次「连接服务器」那个 bug 的另一半。）
  2. **当前最前 app 自己的窗口**。这条防线用来挡住别家 app 的置顶装饰物（桌面宠物、歌词 HUD、悬浮球）—— 它「看得见」不等于「正在被用」。因此别家 app 的 **utility 层（19）**面板会落到下一层，而不是压过当前 app。
  3. **其他任何可用窗口**：空桌面、菜单栏 app、由不激活自己的 agent 弹出的面板，都靠这一层才有洞。都没有就不给焦点、全屏清晰 —— 对这个 app 来说，「丢掉整个模糊」是最不该发生的失败方向。
- 窗口层级按用途分三档：
  - **layer 0**：普通窗口，任何 app 都算。
  - **layer 8 及以上**：系统对话框带 —— 模态面板、认证弹窗、宗卷选择框。它们在最前面是因为有人特意把它们摆在最前面，所以不论属于谁都能当焦点。（「连接服务器」那次的坑：小的「正在连接 smb://…」浮条能当焦点，它弹出的宗卷选择框是模态面板却被层级上限挡掉；随后发现的一半则是：即使层级对，它属于不激活自己的后台进程时，也会被「最前 app 优先」那一步挤掉。）
  - **layer 1–7**：置顶装饰带 —— 浮动 HUD、桌面宠物、歌词条、贴边浮层。只认最前 app 自己的窗口（Quick Look 预览、浮动面板正落在这里），免得别家 app 的宠物抢走焦点。
  - 上限是 Dock（20）：Dock、菜单栏（24）、弹出菜单（101）等永远不能成为焦点。实测确认过这条上限不能放松：Dock 的窗口矩形是**整块屏幕**（layer 20），一旦放行，整屏都会被当成「焦点窗口」。
- 小窗口（小于 120×80）不会被直接否掉，只是**优先级靠后**：一个已经被拖小的合法窗口（迷你播放器、窄工具面板）如果因为尺寸被彻底排除，桌面就会「没有任何可聚焦窗口」，结果是所有覆盖层清空、整屏变清晰。真到只剩这些细碎窗口时，它们仍然能拿到焦点。
- 焦点窗口（连同它的投影）不参与截图，所以它在模糊背景上没有任何边界。因此在洞外画了一圈很淡的**窗沿阴影**（6 层递减描边，共 12pt），并按洞周围背景的明暗自动选黑或白 —— 纯白窗口压在白色背景上也能看清轮廓。阴影画在遮罩层内部，会被挖洞路径裁掉，绝不会盖到窗口上。
- 洞的位置由 **`CVDisplayLink`（与屏幕刷新同步）** 每帧读取，并和模糊图在同一个 `CATransaction` 里提交 —— 两者永远属于同一帧，不会错位。
- 焦点切到别的屏时，洞跟着切到对应屏幕。

## 构建与运行

需要 macOS 14+ 与 Xcode 命令行工具（`Package.swift` 是 swift-tools-version 6.0，所以需要 Swift 6 工具链 / Xcode 16+）。

```bash
./build.sh --run      # 编译、签名并启动
```

单元测试覆盖纯几何与策略逻辑（降采样除数与请求比例、跨屏挖洞圆角、窗口过滤规则、**窗口挑选的分层顺序**、小窗口兜底、覆盖判定），不需要屏幕录制权限，也不需要显示器：

```bash
swift test            # 需要完整 Xcode —— 命令行工具里没有 XCTest
```

代码分为两个 target：`PrivacyCore`（应用逻辑，可被测试导入）与 `PrivacyWindow`（仅入口）。可执行 target 无法被测试模块导入，这是拆开的唯一原因。

首次点击菜单栏「启用隐私模糊」时，macOS 会弹出 **屏幕录制** 权限请求，允许后才会生效。

若没授权，效果会「看起来开着其实不工作」，所以会在 1.5s 后弹一个说明。它是**挂在自己覆盖层上的 sheet**（不是 `runModal()`）：模态循环会独占主线程，期间的显示链路每帧 tick、截图、乃至菜单栏里的「停用」都排在它后面 —— 而弹窗文字本身让用户在之后去点那个菜单项。没有覆盖层可挂载时就不弹。

签名身份用 `SIGN_IDENTITY` 指定；也可以把它写进仓库根目录的 `.sign-identity`（已加入 `.gitignore`），`build.sh` 会自动读取：

```bash
echo 'Developer ID Application: Your Name (TEAMID)' > .sign-identity
./build.sh --run
```

不指定时退回 ad-hoc 签名（`-`），此时每次重新编译都会换一套签名，而 macOS 是按签名记 **屏幕录制** 权限的 —— 所以权限会被反复重新索要，旧的授权还得手动删掉。换成 Developer ID 后 Team ID 固定，授权就能一直生效。

## 使用

菜单栏图标（自定义的「眼睛带斜杠」模板图标；app 图标则是另一幅「窗口浮在模糊桌面上」的图稿）点开后：

- **启用 / 停用隐私模糊**：开关效果。
- **模糊强度**：七档，20%–80%，对应模糊半径 10 / 15 / 20 / 25 / 30 / 35 / 40 pt。原来的轻度 / 中度 / 强度正好落在 20% / 40% / 80%。
- **菜单栏与 Dock 保持清晰**：默认开启。开启时覆盖层降到系统 UI 之下，菜单栏和 Dock 不被模糊、始终可用；关闭后它们会和其余背景一起被模糊。
- **全屏时停止模糊**：默认开启。焦点窗口铺满整块屏幕时（全屏 App），屏幕上已经没有需要隐藏的东西，于是停止模糊也不再截图。
- **退出**。

所有选项（开关状态、模糊强度、菜单栏与 Dock、全屏时停止模糊）都会记在 `UserDefaults` 里，退出后下次启动自动恢复；上次退出时效果是开的，这次启动就直接是开的。

## 说明 / 已知取舍

- 开启「菜单栏与 Dock 保持清晰」（默认）时，覆盖层会降到系统 UI 之下，因此**层级高于菜单栏的界面不会被模糊**：状态栏下拉菜单、弹出菜单、输入法候选栏、通知横幅、Spotlight、Dock 上的拖拽影像等。这是「保证系统 UI 可用」的必然代价；关掉该选项可让覆盖层回到最高层，把它们一并糊上。
- 模糊是**视觉层面**的：覆盖层不拦截鼠标，因此模糊区域背后的窗口其实仍可点击（和 HazeOver 一致）。如果你需要「背景完全不可交互」，需要让覆盖层接收事件，但这会同时挡住焦点窗口的点击——本版本选择保持焦点窗口可交互。
- 多显示器：每张屏幕各有一层覆盖；焦点窗口在哪张屏，洞就挖在哪张屏，其余屏整体模糊。
- 截图会降采样到约 1600px 宽再放大显示：按屏幕宽度缩放，5K/6K 屏最多降到原像素的 1/4，1080p 屏则保持原样；Retina 屏按 `pointPixelScale / divisor` 请求（例如 2560px 宽、2x 的屏，divisor 1.6 → 请求 1.25 px/pt，正好落到 1600px），不会被「最多 1.0」的钳制截掉。模糊本来就会抹掉高频细节，肉眼看不出差别，但像素量（以及模糊开销、GPU→CPU 回读）显著下降，省下的延迟都用在了「跟手」上。
- 桌面静止约 0.75s 后，截图与窗口查询都会自动降频以省电；一旦焦点或窗口位置有变化立刻恢复全速。

## 省电

这是一个常驻菜单栏的工具，所以「没事干的时候别干活」和效果本身一样重要。当前会在这些情况下停止或降低工作：

| 情况 | 行为 |
|---|---|
| 焦点窗口**全屏**（铺满整块屏） | 该屏停止模糊，并**停止截图** |
| 没有可聚焦的窗口（空桌面、锁屏、屏保） | 覆盖层清空 + 截图循环**完全停止** |
| 系统休眠 / 锁屏 / 屏保（通知） | 截图循环停止，唤醒或解锁后恢复 |
| 仅显示器睡眠后唤醒（`screensDidWake`） | 重建显示链路并重新截图 —— 系统休眠才会发 `didWake`，只睡显示器时不会 |
| 时钟自己停了（醒了没通知、未知原因） | 每秒查一次心跳，静默超过 1s 就换一条新的 `CVDisplayLink` |
| 桌面静止（约 0.75s 无变化） | 截图降到 ~30fps，窗口查询降到 1/2 |
| 没有洞的副屏 | 独立降到 ~15fps（整屏模糊，看不出差别） |
| 桌面长时间完全静止（约 15s 无变化） | 截图降到 ~4fps |
| 截图失败（如未授权屏幕录制） | 指数退避 0.25s → 2s，不做无谓重试 |
| 关闭「隐私模糊」 | 所有定时器、任务、窗口全部释放 |

截图还会按屏幕宽度降采样（目标约 1600px 宽、最大 1/4）：屏越大降得越多，模糊本来就会抹掉高频细节，肉眼看不出差别，但像素量和 GPU→CPU 回读随之下降。

> 取舍：全屏时停用模糊，意味着那块屏幕上的一切都是清晰的。判定用的是「窗口是否**铺满整块屏**」而不是「覆盖了多少比例」——覆盖 90% 的窗口仍会留下一条真实的桌面，而那正是这个工具要遮住的东西。

## 代码结构

```
Sources/
  PrivacyWindow/
    main.swift                  // 入口，启动 NSApplication
  PrivacyCore/
    AppDelegate.swift           // 应用代理，挂菜单栏控制器
    StatusItemController.swift  // 菜单栏图标与菜单
    PrivacyController.swift     // 总控：多屏覆盖 + 截图循环 + 焦点洞 + 设置持久化
    DisplayLink.swift           // CVDisplayLink 封装：与屏幕刷新同步的心跳
    FocusTracker.swift          // 找焦点窗口（CGWindowList），含单窗口快速查询
    ScreenCapturer.swift        // 单屏截图（ScreenCaptureKit，排除自身与焦点窗口）
    BlurProcessor.swift         // 洞内补色 + 高斯模糊（Core Image）
    BlurOverlay.swift           // 单屏模糊覆盖窗口 + 透明挖洞
Tests/
  PrivacyCoreTests/             // 纯几何与策略逻辑的单元测试
```
